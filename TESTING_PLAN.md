## Итерация 1. Чистая логика (≈ 0,5–1 день)

**Цель:** вся логика i18n, SEO и роутинга защищена тестами.

### `shared/i18n/config.ts`

- [ ] `isLocale`: `ru` и `en` проходят; `RU`, `""`, `de`, `ru-RU` не проходят
- [ ] `getLocalizedPath`: `home` даёт `/ru` без завершающего слеша, `cases` даёт `/en/cases`
- [ ] `getLocalizedPaths` и `getLocalizedUrls`: в `x-default` стоит `defaultLocale`
- [ ] `getSiteUrl` (через `vi.stubEnv`): берёт значение из env
- [ ] `getSiteUrl`: в dev без env возвращает `http://localhost:3000`
- [ ] `getSiteUrl`: в production без env бросает ошибку

### Словари `ru` и `en`

- [ ] Нет пустых строк
- [ ] Одинаковый набор и порядок `navigation.items` в обеих локалях
- [ ] Для каждого `PluralizedLabel` есть форма для каждой категории `Intl.PluralRules(locale)`

### Вспомогательные функции (сначала вынести из компонентов в `lib/`)

- [ ] Вынести `getLanguageHref` и `isItemActive` из `widgets/header` в `lib/`
- [ ] Тесты `getLanguageHref`: `/ru` → `/en`, `/ru/cases` → `/en/cases`, хвост пути сохраняется
- [ ] Тесты `isItemActive`: главная не активна на `/ru/cases`, `/ru/cases-foo` не подсвечивает «Кейсы»
- [ ] Вынести `getStatusCount` из `CaseBlock` в `lib/`
- [ ] Тесты `getStatusCount`: результат детерминирован и лежит в диапазоне `[2, 1000]`

### Данные и SEO

- [ ] `getMockCaseItems`: одинаковые `slug` в обеих локалях, изображения только с `picsum.photos`
- [ ] `sitemap.ts`: 6 записей (3 страницы × 2 локали), у каждой есть `alternates` с `x-default`
- [ ] `robots.ts`: ссылка на sitemap строится из `getSiteUrl()`
- [ ] `getValidatedLocale` (мок `notFound`): неизвестная локаль вызывает `notFound()`
- [ ] `createPageMetadata` (мок `server-only`): правильные `canonical` и `languages` для каждой пары «страница × локаль»

**Готово, когда:** при поломке словаря, роутинга или SEO-метаданных тест падает с понятным сообщением.

## Итерация 2. Хуки и компоненты (≈ 1–1,5 дня)

**Цель:** клиентская логика и a11y-атрибуты проверяются автоматически.

### `useRetroWindowAnimation` (fake timers)

- [ ] «Свернуть» в развёрнутом состоянии сворачивает окно
- [ ] Повторное «свернуть» на свёрнутом окне запускает `shaking` на 800 мс, окно остаётся свёрнутым
- [ ] «Полный экран» на свёрнутом окне разворачивает его
- [ ] «Полный экран» на развёрнутом окне запускает `jello` на 800 мс
- [ ] Закрытие сбрасывает `shaking` и `jello`, через 1000 мс снимает `isClosed` и `isCollapsed`
- [ ] Быстрые повторные клики не оставляют висящих таймеров
- [ ] При размонтировании таймеры очищаются, `setState` после этого не вызывается

### Компоненты

- [ ] `RetroWindow`: у трёх кнопок есть доступные имена из `controlLabels`
- [ ] `RetroWindow`: после сворачивания контент получает `aria-hidden`
- [ ] `TypewriterTextSequence`: пустой `texts` даёт `null`
- [ ] `TypewriterTextSequence`: полный текст всегда есть в `sr-only`
- [ ] `TypewriterTextSequence`: при `startDelay` печать начинается после таймера, при размонтировании таймер очищается
- [ ] `Header` (мок `usePathname`): `aria-current="page"` только на активном пункте
- [ ] `LanguageSwitcher`: ссылки ведут на ту же страницу в другой локали

### `useActiveNavigationIndicator` (мок `getBoundingClientRect` и `ResizeObserver`)

- [ ] Без активной страницы индикатор равен `null`
- [ ] Размеры округляются до 2 знаков
- [ ] Если размеры не изменились, повторного `setState` нет

**Готово, когда:** каждый хук и интерактивный компонент имеет тест на основной сценарий и на граничные случаи.

## Итерация 3. Исправление найденных багов (≈ 0,5 дня)

**Цель:** оба бага закрыты, и для каждого есть тест. Порядок: красный тест → исправление → зелёный тест.

### Баг 1. Счётчик «objects» не локализован

`src/views/cases/ui/RetroWindow.tsx:128` выводит `{objectsCount} objects`, а ключ `pages.cases.status.objects` из словарей не используется.

- [ ] Написать падающий тест: на `/ru` счётчик выводится по правилам плюралей из словаря
- [ ] Исправить: брать форму из словаря через `Intl.PluralRules`, передать `locale` и подписи в `RetroWindow`
- [ ] Тест зелёный

### Баг 2. Кнопка «Подробнее» ведёт на 404

`CaseBlock` строит ссылку `/${locale}/cases/${slug}`, но страницы `src/app/[locale]/cases/[slug]` нет.

- [ ] Решить продуктово: сделать страницу кейса или временно скрыть кнопку
- [ ] Реализовать выбранное решение
- [ ] Зафиксировать поведение тестом (может быть E2E из итерации 4)

**Готово, когда:** баги не воспроизводятся, а тесты не дают им вернуться.

## Итерация 4. E2E на Playwright (≈ 1–1,5 дня)

**Цель:** сквозные сценарии роутинга, SEO и навигации проверяются на настоящей сборке.

### Настройка

- [ ] Поставить `@playwright/test` и браузеры (`bunx playwright install --with-deps chromium`)
- [ ] Создать `playwright.config.ts`: `webServer` запускает `next build && next start`, проекты `desktop` и `mobile`
- [ ] Добавить скрипт `test:e2e`
- [ ] Добавить в `.gitignore` `test-results/` и `playwright-report/`
- [ ] Добавить шаг E2E в CI после `build` (с `NEXT_PUBLIC_SITE_URL`), сохранять `trace` упавших тестов

### Редиректы `proxy.ts`

- [ ] `/` с `Accept-Language: en-US` ведёт на `/en`
- [ ] `/` с `ru` или без заголовка ведёт на `/ru`
- [ ] `/cases?x=1` ведёт на `/ru/cases?x=1` (query сохраняется)
- [ ] `/robots.txt`, `/sitemap.xml`, `/favicon.ico`, `/_next/...` не редиректятся
- [ ] `/en/cases` не редиректится
- [ ] `/de` отдаёт 404 (`dynamicParams = false`)

### Страницы и навигация

- [ ] Smoke-проход по всем 6 страницам (3 страницы × 2 локали): статус 200
- [ ] На каждой странице проверить `title`, `description`, `canonical`, `hreflang`
- [ ] На каждой странице нет ошибок в консоли (включая ошибки гидратации)
- [ ] Клик по пункту меню меняет URL и `aria-current`
- [ ] Переключение языка на `/ru/cases` ведёт на `/en/cases`
- [ ] Ни одна внутренняя ссылка на страницах не отдаёт 404
- [ ] Окно кейса сворачивается, разворачивается и закрывается с клавиатуры (Tab, Enter, пробел)

**Готово, когда:** E2E стабильно проходят локально и в CI на desktop и mobile.

## Итерация 6. Закрепление (≈ 0,5 дня)

**Цель:** любой разработчик понимает, как писать и запускать тесты, а CI не пропускает регрессии.

- [ ] Включить `test:coverage`, задать порог для логики (например, 80% для `shared/` и `lib/`); для UI не гнаться за цифрой
- [ ] Добавить прогон связанных тестов (`vitest related`) в `lint-staged`
- [ ] Обновить `CLAUDE.md` (разделы Commands и Verification: «no test runner» больше неверно)
- [ ] Обновить `README.md`: как запускать тесты, где они лежат, как обновлять скриншоты
- [ ] Финальный прогон: `bun run check`, E2E и `bun run fsd:check` проходят
- [ ] Удалить или заархивировать этот файл, когда всё выполнено
