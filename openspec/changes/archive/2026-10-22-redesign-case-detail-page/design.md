# Design

## Context

`src/views/case-details/ui/CaseDetailPage.tsx` is one component: `ImageWithFallback` beside a `RetroWindow` holding the name, project link, description, a facts `dl`, achievements and a back button. `CaseDetail` already carries `backgroundImage` / `backgroundBlurImage` (both nullable), `category`, `stack` and `achievements`, so no API work is needed. The page is a Server Component (SSG); nothing here needs client state. Styling is Tailwind 4 with the retro tokens (`canvas`, `accent`, `font-vcr`, `focus-ring`). `public/` is empty, and the carbontec source draws the code frame with `border-image: url("/code-border.png") 25` (a 166x168 px corner sprite).

## Goals / Non-Goals

**Goals:**

- Reproduce the carbontec case layout (hero header, "About case", highlighted blocks) in our retro style and structure.
- Keep every existing fact and null rule of the `case-details` spec working.
- Keep the page a Server Component, split into focused components inside the `case-details` slice.

**Non-Goals:**

- Sharing the new components through `shared/ui` (no second consumer yet).
- Reproducing the carbontec SCSS pixel for pixel, or its other sections.

## Decisions

**Components in the slice.** `CaseDetailPage` becomes a thin composition of `CaseHeader`, `CaseAbout`, `CaseStack` and `CaseAchievements` in `views/case-details/ui/`, each taking only the props it needs plus its dictionary part. Alternative: one file with local functions. Rejected: the sections are tested separately and the project rule is to split large JSX blocks.

**Header background behind the site menu.** The site `Header` (menu and language switcher) is a separate grid row above `main`, so a background inside the case header started below it and ended in a hard edge against the black menu strip. The background now starts at the top of the page: `body` in `SiteLayout` is `relative`, the case header is not positioned, and the background is an absolutely positioned block (`inset-x-0 top-0`, about 480 px high, 560 px from `md`, `-z-10`) that is anchored to `body`, so it does not need to know the height of the menu. Inside it a `next/image` with `fill`, `object-cover object-top`, `placeholder="blur"` when `backgroundBlurImage` exists, `priority`, `sizes="100vw"` and a decorative `alt=""`. The edges are dissolved with a CSS mask on the image block (`mask-image`: transparent at the top, opaque after about 140 px, transparent at the bottom; from `lg` also a soft horizontal fade), not with colour overlays, so the picture melts into the page background whatever the picture is. A light dark scrim over the top 160 px keeps the menu readable on bright pictures. With `backgroundImage: null` the block is not rendered and the header is a plain dark area with no "no image" text, because the background is decorative. `ImageWithFallback` is not reused: its fallback box and fixed aspect ratio do not fit a decorative background. The case picture `image` is not shown on this page at all (it stays in the list). Alternatives: only fade the edges of the picture inside the header (rejected: the menu still sits apart from the picture); a framed banner with rounded corners (rejected: loses the full-width hero and adds a third frame style); a transparent site header on every page (rejected: changes all pages for one).

**Facts as labelled cells with icons in the header.** Role, company, team size and period stay a `dl` (a `dt`/`dd` pair per fact, `dt` before `dd` in the DOM, wrapped in a `div` per fact), so the null handling, the formatting (`formatMonth`, `periodPresent`) and the semantics move over unchanged; the period value keeps its `capitalize`. The first version put each pair on one line (`label value`) with only a gap between pairs, so the pairs merged. Each fact is now a cell with the muted label above the value, separated from its neighbours by dashed `border-white/20` dividers (the same language as the achievements). A translucent panel (dashed border, `bg-canvas/50`, `backdrop-blur-sm`) was tried and dropped: the block lies directly on the picture, with no outer border and no fill, and only the dividers between cells remain. From `lg` the cells are one row with a vertical divider between neighbours (`lg:[&>div+div]:border-l`); below `lg` they form a two-column grid, a cell from the second row gets a top divider and a cell in the right column a left divider (`nth-child` selectors), which keeps the dividers right for three or four cells. Missing `company` / `teamSize` render no cell, so a case with two facts shows two cells. Each cell has a small pixel icon (14 px, `currentColor`, `text-white/60`, like the label) before its label: a person for the role, a calendar for the period, a building for the company, a group for the team. The icons are decorative (`aria-hidden`, `focusable="false"`), drawn on a 12x12 pixel grid with `shape-rendering="crispEdges"`, and live as `.svg` files in `views/case-details/ui/assets/` imported with the `?svgr` query, as the other icons of the project. Alternatives: pills per fact (rejected: noisy beside the stack and achievements); a vertical list (rejected: four rows of height); a text-only block (rejected: harder to scan than with icons). Risk: without the panel the labels lose the contrast help on bright pictures; if they are hard to read in Playwright, add a light `text-shadow` or a stronger dim behind the block, not a frame. The cells are ordered role, period, company, team, so the short team cell comes last. The team label is the short "Команда" / "Team" (the long "Размер команды" looked out of proportion next to a two-digit value) and the value is the number plus a unit that agrees with it: "человек" with the Russian plural forms from `Intl.PluralRules` (1, 21 -> "человек"; 2-4, 22-24 -> "человека"; 0, 5-20, 25-30 -> "человек") and "person" / "people" in English. The dictionaries carry the unit forms (`teamSizeUnit`, a record by plural category with `other` required) and the header picks the form with `new Intl.PluralRules(locale).select(teamSize)`. Alternatives: the abbreviation "чел." (rejected: still needs "person" / "people" in English and reads as officialese); "участников" or "разработчиков" (rejected: the backend sends only a number, so the composition of the team is unknown).

**Back link in the header.** The existing `Button` link to `getLocalizedPath("cases", locale)` is not reused as is: it is a full-width control. The header uses a small text link in the `ExternalLink` style (`font-vcr`, uppercase, accent, same hover/focus/active states) with an arrow icon. The existing `backToCases` dictionary key provides the text.

**Project link.** `ExternalLink` is reused unchanged, with the existing `aria-label` that includes the case name.

**Stack card with `border-image`.** `public/code-border.png` is copied from carbontec. The sprite is not just a frame: its top, right and inner strips are opaque white and only the left and bottom strips carry the stepped lines, so the card is white where the sprite is and the lines sit on the dark page. The card draws it with a transparent border (25 px from `sm`, 12 px below) and one `border-image` shorthand that sets slice, width and outset together, because Tailwind emits a shorthand after a longhand and a separate `border-image-outset` class is reset to 0. The outset moves the strips 5 px outward (2 px on narrow screens), which leaves a gap to the padding box; the image width is therefore the border plus the outset (`25/30px/5px` from `sm`, `25/14px/2px` below) so the strips meet the card interior. `bg-clip-padding` keeps the CSS white fill inside the padding box so the transparent top-left corner of the sprite stays dark. This matches the reference picture supplied by the user (white card, lines at the left and the bottom). The technologies render as a `ul` of `li` in `font-mono`, laid out as a wrapping row (`flex-row flex-wrap`, small gaps) so the card stays short, each prefixed with a decorative `/`. Alternatives: one column per technology (rejected: too tall); the carbontec `::after` white layer (rejected: it also fills the transparent corner and needs a pseudo element); `bg-clip-padding` with the default image width (rejected: leaves a dark gap around the card).

**Achievements.** The section is titled "Achievements" ("Достижения"), not "Challenges", and its title is larger than the other section titles (24 px, 32 px from `sm`, against 18 px and 24 px) so the block stands out. Each achievement is an article with the title (bold, white) first, then the description, then the result, which is the `metric` field, as a plain bold white line (no large VCR type, because real metrics are sentences, not numbers). Items are separated by a dashed rule (`border-dashed border-white/20`) and each carries a pixel index ("01", "02", ...) in `font-vcr` muted (`text-white/40`), placed to the left of the text from `sm` and above the title on narrow screens. The index and the rule are decorative (`aria-hidden`), so the accessible text of an item stays title, description, result. Alternatives: a small white pixel square marker without numbers (rejected: too faint); a framed card per item (rejected: competes with the stack card). The section is omitted when `achievements` is empty (the backend allows it). The component is `CaseAchievements` and the dictionary key `achievementsTitle`.

**Period dates.** `formatMonth` builds "month year" from `Intl.DateTimeFormat` parts and joins only the month and year parts, so the Russian year suffix "г." is dropped ("апрель 2023 – сентябрь 2026") while English stays "April 2023 – September 2026". Alternative: strip "г." from the formatted string with a regex. Rejected: it depends on the exact literal and breaks silently for other locales.

**Dictionary.** Add `aboutTitle`, `achievementsTitle` and `stackTitle` to the `Dictionary` type and both `ru` and `en`. `stackLabel` is removed because the facts `dl` no longer contains the stack; `categoryLabel` is removed because the category is now the header kicker. `satisfies Dictionary` keeps both locales in sync.

**Colour.** The accent (purple) colour is reserved for interactive elements: the back link and the project link, with their hover, focus and active states. Section titles ("About case", "Stack", "Achievements") and the achievement metric are white, the category and the fact labels are muted (`text-white/60`), the description and achievement texts stay `text-white/80`. Alternative: keep accent titles as in the retro list page. Rejected: too many purple labels competed with the links. The decorative achievement index is muted (`text-white/40`), not accent.

**Layout.** One scroll container as today (`size-full overflow-y-auto`), the header full-bleed with a max width around 1440 px, the sections in a `max-w` content column. "About case" is a two-column grid from `lg` up (title left, text and link right) and a single column below, as in carbontec. Mobile gets 16 px gutters and no horizontal scroll.

**Component structure: visually clean components by FSD segment.** `CaseHeader` had grown to one file that mixed formatting helpers (`formatMonth`, `formatTeamSize`), data assembly (the period and the null rules spread over the JSX), a second component (`FactLabel`), types, a class constant and large markup. It is split by responsibility into files of the matching FSD segment inside the `case-details` slice: `lib/formatPeriod.ts` (month and year without the Russian "г.", the "present" wording), `lib/formatTeamSize.ts` (the number plus a unit by `Intl.PluralRules`), `lib/getCaseFacts.ts` (the order of the facts and the null rules, returning a list of `{ id, label, value }`), `model/types.ts` (`CaseFactId`, `CaseFact`), and a folder `ui/CaseHeader/` with `CaseHeader.tsx` (composition only), `CaseBackground.tsx` (the layer with the mask and the scrim), `CaseBackLink.tsx`, `CaseFacts.tsx` (the `dl`, a plain `facts.map(...)` with no conditions or formatting), `FactLabel.tsx`, `factIcons.ts` (the id to icon map), the `assets/` icons and an `index.ts`. Behaviour, markup and styling do not change, so the specs do not change, and the public API of the slice is the same. The other components of the slice (30 to 55 lines each) are already clean and stay. Alternatives: leave the file as it is (rejected: it is the file people copy from); move class strings to a `styles.ts` (rejected: the strings are short once the components are small, and a constants file hides the markup from the Tailwind linter); put the helpers in `shared` (rejected: there is no second consumer, and `CLAUDE.md` moves code to `shared` only when a second slice needs it). The rule is written into `CLAUDE.md`: a component file holds one component and its props type, JSX is declarative, and helpers, types, constants and requests go to `lib/`, `model/`, `config/` and `api/` in their own files; a second component, a helper, a data type or more than about 100 lines is the signal to extract. It is backed by the ESLint rule `react/no-multi-comp` as a warning (not an error, so that existing code is not blocked); the two existing warnings (`ButtonContent` in `shared/ui/Button.tsx`, `IntroContent` in `views/home/ui/HomePage.tsx`) are fixed in a separate commit, not in the feature work.

## Risks / Trade-offs

- [The hero background is a large image on the case route] -> `next/image` with `sizes="100vw"`, `priority`, and the blur placeholder; the stub and production storage host is already allowed in `next.config.ts`.
- [Text over an arbitrary photo can be unreadable] -> the gradient plus a dark overlay under the title, and a check of contrast on desktop and mobile in the Playwright pass; the muted labels (`text-white/60`) are the weakest case, so keep them on the darkest part of the overlay.
- [An absolutely positioned background may not scroll with the content, because the page scrolls inside `overflow-y-auto` of `CaseDetailPage`] -> check by scrolling in Playwright on desktop and mobile; if it stays pinned, move the scrolling to the document or anchor the block inside the scroll container.
- [`body` becomes `relative` for every page] -> it only creates a containing block and changes nothing visually; the other pages are checked by the existing e2e smoke tests.
- [Without the case picture the page loses its second visual] -> the header background carries the visual; a case without a background is a plain dark header, which is accepted.
- [`border-image` with a 25 px border eats width on narrow screens] -> reduce the border slice and padding below `sm` and check 360 px wide.
- [The case spec and e2e currently assert `dt` counts and the `RetroWindow` shape] -> the tests are rewritten in the same change, red first.
- [Dictionary key renames break the list page if shared] -> `achievementsTitle`, `stackLabel` and `categoryLabel` are only used by `CaseDetailPage` (verified with grep); `backToCases` stays.

## Open Questions
